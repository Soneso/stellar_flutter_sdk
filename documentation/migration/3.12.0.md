# Migrating to 3.12.0

This guide covers the observable changes between 3.11.0 and 3.12.0. If you upgrade from an older version, also review the CHANGELOG between your version and 3.11.0 and the earlier migration guides, newest first: [3.9.0](3.9.0.md), [3.8.0](3.8.0.md), [3.6.0](3.6.0.md). Each note describes one situation: whether you are affected, how it shows, and what to do.

- If you `switch` over `OZContextRuleType` with a case for each subclass and no `default` clause: in 3.12.0 the code does not compile, because the type gains `OZContextRuleTypeCreateContractExternalRef(owner, tag)`, the rule for contracts deployed from an executable reference. The analyzer reports `The type 'OZContextRuleType' isn't exhaustively matched by the switch cases since it doesn't match the pattern 'OZContextRuleTypeCreateContractExternalRef()'.` `listContextRules` returns such rules, and the kit signs for wallets that hold one. In 3.11.0 `listContextRules` and the kit's signing operations threw `SmartAccountInvalidInput` with `Invalid input for context_type: Unknown context_type discriminant: CreateContractExternalRef` for such a wallet. Add a case `OZContextRuleTypeCreateContractExternalRef(:final owner, :final tag)`, or a `default` clause (in a `switch` expression, a `_` case).
- If you add a contract (`C...`) as a Delegated signer: in 3.12.0 `OZSignerManager.addDelegated` and `OZContextRuleManager.addContextRule` throw `SmartAccountInvalidAddress`. For the wallet itself, they throw `SmartAccountInvalidInput`. `OZTransactionOperations.submit` and `OZMultiSignerManager.submitWithMultipleSigners` apply these checks only to `add_signer`, `batch_add_signer`, and `add_context_rule` on the connected wallet, after simulation and before asking any signer. Raw self-delegation can fail simulation first with `SmartAccountTransactionSimulationFailed` reporting 3018 `SelfDelegatedSigner`. In 3.11.0 the SDK allowed contract delegates. Catch `SmartAccountException` for validation and transaction failures. Add the Stellar account (`G...`) that should sign. Existing contract delegates remain readable, and the kit still signs. Remove them with `OZSignerManager.removeSignerBySigner`, or upgrade the wallet and every smart account it delegates to, to stellar-accounts 0.7.3 or 0.8.0.
